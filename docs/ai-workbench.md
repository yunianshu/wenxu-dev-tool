# AI 工作台

## 日常使用

1. **先记录**：收件箱输入一句话，按 Enter 保存。复杂内容用「新建记录」，支持 Markdown 与按类型插入模板。
2. **关联项目**：在记录中选择项目，或从「项目 → 知识记录」新建。项目备注继续承载项目简介，记录用于持续积累。
3. **整理**：类型（想法、问题、决策、经验、方法、SOP、原则、AI 技巧）与整理状态（待整理、草稿、已整理、已归档）分别设置。搜索同时查找标题、正文、标签和项目名称。
4. **AI 提炼**：勾选记录后点击「整理所选」，或直接「分析想法」。确认来源和目标后开始；使用「设置 → AI 服务」中已有模型，只发送明确选择的内容。
5. **保留证据**：AI 分析前先保存原始输入；分析结果可编辑后保存为草稿，来源可点击返回。验证过的方法再手动标记为已整理，原文不会被替换。

可用快捷操作：Enter 快速记录、Ctrl/Cmd+S 立即保存、Ctrl/Cmd+K 搜索、右键记录操作、双击聚焦编辑、拖入 Markdown 导入。删除只移入回收站，可恢复。

## 文件与可靠性

- 正式记录存于应用用户数据目录的 `knowledge/<UUID>.md`。工作台右上角更多菜单可以打开目录。
- 每份文件由 YAML 元信息与 Markdown 正文组成，元信息保存类型、状态、项目、来源、时间与修订号；一个记录对应一个稳定 ID。
- 输入后约 600ms 自动保存；Ctrl/Cmd+S 可立即保存。未保存编辑同时保存在本机 Webview 草稿缓存中，应用重启后恢复并尝试写回。AI 面板中尚未提交的输入与生成草稿也有本地恢复缓存。
- 保存采用临时文件、原子替换、版本与文件摘要校验。其他进程或编辑器改过文件后，旧草稿不会直接覆盖，界面会提示；可将本地草稿另存为新记录后刷新核对。
- 保存失败会保留当前草稿；请重试，或另存副本。读取损坏文件会报告文件名并保留原文件。
- 项目删除不会级联删除记录，历史项目名称仍可查看和筛选。
- 导入/导出支持 Markdown；导入总是创建新 ID，不覆盖已有记录。直接放入知识目录的文件需符合应用元信息格式，普通 Markdown 请从菜单或拖放导入。
- 如需 Git 管理，可自行管理知识目录的 Markdown 文件。本版本不自动创建仓库、提交或联网同步，也不定时发送知识给 AI。
