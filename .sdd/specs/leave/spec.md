# 一键请假规格

## 目标与边界

读取本人北森出勤与假期余额，为迟到生成可核对的请假方案，由用户确认后按日期倒序提交。默认处理本月第一天至今天，允许选择历史日期范围；默认上班 08:30、下班 17:30。单次迟到超过 15 分钟必须请假：08:30–08:45 到岗优先走每月额度（最多 5 次、合计 50 分钟），额度够则不申请；08:46–09:15 请 0.5 小时且 09:00 后余量计入额度，额度不足升级为覆盖到岗的整段请假；09:16 起按有效迟到时长（扣除午休 12:00–13:00）向上取整到半小时请假，一天最多 8 小时。假种按天级联：整段调休 → 整段年假 → 调休+年假分段拼够 → 事假补差额。每天可切换“计算迟到”（勾选少请 0.5 小时、余量计额度；取消多请 0.5 小时、剩余迟到归零），确认弹窗可按天改假种并显示剩余迟到。不自动处理缺卡、早退、全天旷工、其他人的出勤；开发验证不提交真实请假。

## 业务规则与验收

- R1 出勤优先：[点击生成方案] → 读取选区涉及自然月的完整实际首打卡和已有请假（当前月截至今天），再读取可用假种和实时余额；选区外已经发生的额度内迟到、已有请假覆盖后的余量优先占用月度额度，只为选区内生成申请；完整月份数据参与提交指纹。读取失败或字段不明时明确失败，不产生可提交方案。
- R2 迟到请假块：[首打卡晚于上班且早于下班] → 先舍弃首打卡秒数。到岗在上班后 15 分钟内：每月额度（5 次、50 分钟）足够则不申请并显示计入额度；额度不足请 0.5 小时。到岗在 08:46–09:15：请上班后 0.5 小时；09:00 后余量（≤15 分钟）计入额度，额度不足时升级为覆盖到岗时刻的整段请假。到岗在 09:16 之后：按有效迟到时长（扣除午休 12:00–13:00）向上取整到半小时请假，一天最多 8 小时。
- R3a 调休条目限制：[分配调休] → 按调休记录条目（加班获得日 OvertimeDate、有效期 ValidityDate、剩余 Balance）分配，同时受表单总余额上限限制，多日、指定假种、分段均不得超额；条目对获得日及之后的请假日有效（当天加班可抵当天迟到）且请假日不超过有效期；条目未提供时回退总额限制。指定调休但当天不可用时改用级联并说明。方案携带条目明细，点击调休余额卡可查看（加班日/剩余/可用区间）。
- R3 假种级联：[当天需要请假] → 优先整段调休；调休余额不足改整段年假；年假单独也不足时用调休+年假按有效工时分段拼够；两者合计仍不足的差额用事假补足（事假不设余额上限）。用户指定单日假种时按指定假种整段申请，余额不足则阻断该日并提示改选。平台拒绝某假种时当天自动降级重算。
- R4 倒序：[存在多天记录] → 按日期倒序分配与提交；余额不足以覆盖较旧日期时由事假补足。
- R5 月度额度三条件同时成立：[存在多次迟到记录] → 每个自然月不请假的迟到最多 5 次、合计不超过 50 分钟、每次不超过 15 分钟（时间窗已保证）；09:00–09:15 的余量优先占用额度，08:30–08:45 的迟到随后；额度放不下（含用户手动勾选）的一律自动改为多请 0.5 小时，不生成超额方案；方案携带 quota 摘要（X/5 次 · Y/50 分钟）供界面展示。
- R5c 方案留存：[生成或调整方案后] → 方案与显式 overrides 留存于本机；后台重启/页面重进时恢复假种选择、工作时间并可继续调整与提交（有效期从恢复时刻重新起算，提交前仍全量复核）；旧版缺少完整月份核对的方案提示重新生成；提交、解除或主动重新连接后清除，连接状态轮询不清除方案。配置修改后切页不得复活旧方案。
- R5a 逐行调整：仅余量大于 0 的日期显示“计算迟到”开关（08:46–09:00 到岗余量为 0，固定基础请假且忽略 countLate）；恢复留存方案时按当前规则重算，保留用户调整（overrides 一并留存）。：[明细表或确认弹窗] → 每天可切换“计算迟到”（勾选 = 基础请假 + 余量计入额度；取消 = 多请 0.5 小时且剩余迟到归零），可改假种（自动/调休/年假/事假），调整后立即重算时长、分段、余额和剩余迟到；提交使用调整后的方案。
- R5b 部分提交：[方案含多天] → 确认弹窗可按天勾选，仅提交勾选日期；同一天的分段整体提交，只认方案内日期，未勾选日期不写入；提交后原方案失效，剩余日期需重新生成。
- R5d 覆盖余量计入额度：[已有请假覆盖到岗前的时段] → 覆盖终点之后的迟到分钟（≤15）作为既成事实优先计入当月额度并在行内显示剩余迟到；额度卡展示“还可用 X 次 · Y 分钟 / 已用 Y/限额”。
- R6 防重复：[已有审批中或已通过的请假覆盖到请假块终点，或存在无法辨别的重叠] → 跳过或阻止该记录，不重复扣减余额；缺卡和没有迟到的日期明确显示跳过原因。
- R7 明确确认：[尚未确认、方案已更改或数据已过期] → 禁止提交；用户核对日期、假种、起止时刻、扣减和余额并点击确认后，仅提交确认的方案。
- R8 重新核对：[确认后准备写入] → 再查出勤、已有申请和余额；与预览产生实质变化时停止，要求重新生成和确认。
- R9 顺序失败处理：[批量写入中出现错误或结果不确定] → 停止后续写入，分别显示已成功与未提交记录；重试前必须重新获取平台记录，禁止盲目重发。
- R10 登录与隐私：[浏览器未登录或连接不可用] → 显示可操作的连接/登录提示；书签桥限定北森考勤来源和本机 Host，持久配对凭据经系统凭据库保存，任务及回调使用每次连接独立的会话凭据；内嵌回调也须认证。新书签使用固定配置端口，应用重启可恢复读取通道，同页重连替换旧轮询，不自动重发申请。旧版书签首次升级需重新复制；端口占用、凭据库不可用或本地网络权限被拒时提示重试或内嵌登录。兼容旧版 CORS/PNA 预检，同时提示新版浏览器的本地网络权限，不修改浏览器安全设置。企微捕获覆盖 Chrome/Edge/Brave 多配置。复用本人已登录浏览器，不保存 Cookie、口令、页面签名或原始敏感响应。
- R11 兼容：[从桌面页面调用] → Tauri 与 Electron 使用相同后端契约；切换视图时保留正在执行的状态及重算锁，所有配置修改入口使用同一锁；配置变化后的旧响应必须丢弃，防止并发生成或提交。

## 验证范围

用纯函数测试覆盖取整、边界、倒序和余额分配；用隔离平台适配器覆盖确认门、重新核对、失败中止与防重复；用真实页面只读验证字段和余额，使用隔离页面/接口验证提交流程；构建验证 Vue 页面与双桌面桥接。
