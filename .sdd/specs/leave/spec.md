# 一键请假规格

## 目标与边界

读取本人北森出勤与假期余额，为迟到生成可核对的请假方案，由用户确认后按日期倒序提交。默认处理本月第一天至今天，允许选择历史日期范围；默认上班 08:30、下班 17:30。每笔固定申请上班后 0.5 小时，09:00 后最多再迟到 15 分钟；每月最多 5 次、09:00 后余量合计不超过 50 分钟，到岗不晚于 10:00。假种顺序为调休 → 年假 → 事假/请假，调休优先分配给原始迟到较长的日期。不自动处理缺卡、早退、全天旷工、其他人的出勤或其他假种；开发验证不提交真实请假。

## 业务规则与验收

- R1 出勤优先：[点击生成方案] → 先获取指定范围的实际首打卡和已有请假，再读取可用假种和实时余额；读取失败或字段不明时明确失败，不产生可提交方案。
- R2 迟到请假块：[首打卡晚于上班且早于下班] → 先舍弃首打卡秒数；每笔请假固定覆盖上班后 0.5 小时（默认 08:30–09:00），09:00 后最多允许再迟到 15 分钟且不再多请；到岗超过 09:15 或晚于 10:00 时该日阻断并说明原因。
- R3 假种顺序：[当天需要请假] → 优先调休假；调休余额不足时改用年假；年假不足时改用事假/请假（不设余额上限，由平台校验兜底）。同一日期只使用一种假种；余额不足以覆盖 0.5 小时时该日阻断并保留余额。
- R4 调休分配：[调休余额不足以覆盖所有日期] → 按原始迟到分钟从长到短分配调休，短迟到留给年假/事假；提交仍按日期倒序。
- R5 月度上限：[存在多次迟到记录] → 每个自然月最多处理 5 次；09:00 后的迟到余量合计不超过 50 分钟；超出额度的日期阻断并说明原因。
- R6 防重复：[已有审批中或已通过的请假覆盖到请假块终点，或存在无法辨别的重叠] → 跳过或阻止该记录，不重复扣减余额；缺卡和没有迟到的日期明确显示跳过原因。
- R7 明确确认：[尚未确认、方案已更改或数据已过期] → 禁止提交；用户核对日期、假种、起止时刻、扣减和余额并点击确认后，仅提交确认的方案。
- R8 重新核对：[确认后准备写入] → 再查出勤、已有申请和余额；与预览产生实质变化时停止，要求重新生成和确认。
- R9 顺序失败处理：[批量写入中出现错误或结果不确定] → 停止后续写入，分别显示已成功与未提交记录；重试前必须重新获取平台记录，禁止盲目重发。
- R10 登录与隐私：[浏览器未登录或连接不可用] → 显示可操作的连接/登录提示；复用本人已登录浏览器，不保存 Cookie、口令、页面签名或原始敏感响应。
- R11 兼容：[从桌面页面调用] → Tauri 与 Electron 使用相同后端契约；切换视图时保留正在执行的状态，防止并发生成或提交。

## 验证范围

用纯函数测试覆盖取整、边界、倒序和余额分配；用隔离平台适配器覆盖确认门、重新核对、失败中止与防重复；用真实页面只读验证字段和余额，使用隔离页面/接口验证提交流程；构建验证 Vue 页面与双桌面桥接。
