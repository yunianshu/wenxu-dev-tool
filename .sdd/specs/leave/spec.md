# 一键请假规格

## 目标与边界

读取本人北森出勤与假期余额，为迟到生成可核对的请假方案，由用户确认后按日期倒序提交。默认处理本月第一天至今天，允许选择历史日期范围；默认上班 08:30、下班 17:30。单次迟到超过 15 分钟必须请假：08:30–08:45 到岗优先走每月额度（最多 5 次、合计 50 分钟），额度够则不申请；08:46–09:15 请 0.5 小时且 09:00 后余量计入额度，额度不足升级为覆盖到岗的整段请假；09:16 起按有效迟到时长（扣除午休 12:00–13:00）向上取整到半小时请假，一天最多 8 小时。假种按天级联：整段调休 → 整段年假 → 调休+年假分段拼够，合计不足该日先不处理。不自动处理缺卡、早退、全天旷工、其他人的出勤或其他假种；开发验证不提交真实请假。

## 业务规则与验收

- R1 出勤优先：[点击生成方案] → 先获取指定范围的实际首打卡和已有请假，再读取可用假种和实时余额；读取失败或字段不明时明确失败，不产生可提交方案。
- R2 迟到请假块：[首打卡晚于上班且早于下班] → 先舍弃首打卡秒数。到岗在上班后 15 分钟内：每月额度（5 次、50 分钟）足够则不申请并显示计入额度；额度不足请 0.5 小时。到岗在 08:46–09:15：请上班后 0.5 小时；09:00 后余量（≤15 分钟）计入额度，额度不足时升级为覆盖到岗时刻的整段请假。到岗在 09:16 之后：按有效迟到时长（扣除午休 12:00–13:00）向上取整到半小时请假，一天最多 8 小时。
- R3 假种级联：[当天需要请假] → 优先整段调休；调休余额不足改整段年假；年假单独也不足时用调休+年假按半小时边界分段拼够（两段首尾相接）；两者合计仍不足则该日先不处理。平台拒绝某假种时当天自动降级重算。
- R4 倒序：[存在多天记录] → 按日期倒序分配与提交，余额合计不足时较旧记录先不处理。
- R5 月度额度：[存在多次迟到记录] → 每个自然月不请假的迟到最多 5 次、合计不超过 50 分钟；09:00–09:15 的余量优先占用额度，08:30–08:45 的迟到随后；额度不足的日期改为请假并说明原因。
- R5a 部分提交：[方案含多天] → 确认弹窗可按天勾选，仅提交勾选日期；同一天的分段整体提交，只认方案内日期，未勾选日期不写入；提交后原方案失效，剩余日期需重新生成。
- R6 防重复：[已有审批中或已通过的请假覆盖到请假块终点，或存在无法辨别的重叠] → 跳过或阻止该记录，不重复扣减余额；缺卡和没有迟到的日期明确显示跳过原因。
- R7 明确确认：[尚未确认、方案已更改或数据已过期] → 禁止提交；用户核对日期、假种、起止时刻、扣减和余额并点击确认后，仅提交确认的方案。
- R8 重新核对：[确认后准备写入] → 再查出勤、已有申请和余额；与预览产生实质变化时停止，要求重新生成和确认。
- R9 顺序失败处理：[批量写入中出现错误或结果不确定] → 停止后续写入，分别显示已成功与未提交记录；重试前必须重新获取平台记录，禁止盲目重发。
- R10 登录与隐私：[浏览器未登录或连接不可用] → 显示可操作的连接/登录提示；复用本人已登录浏览器，不保存 Cookie、口令、页面签名或原始敏感响应。
- R11 兼容：[从桌面页面调用] → Tauri 与 Electron 使用相同后端契约；切换视图时保留正在执行的状态，防止并发生成或提交。

## 验证范围

用纯函数测试覆盖取整、边界、倒序和余额分配；用隔离平台适配器覆盖确认门、重新核对、失败中止与防重复；用真实页面只读验证字段和余额，使用隔离页面/接口验证提交流程；构建验证 Vue 页面与双桌面桥接。
