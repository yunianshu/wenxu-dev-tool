# 实现设计

- 配置保存在 `targets[].openclaw`，默认关闭；前后端工厂与规范化保持一致，复制服务器配置不继承项目专属同步设置。
- 新增本地 OpenClaw 发布模块：验证路径及插件/Skill 元数据，按既有发布忽略规则筛选源文件，再将选定文件及 SHA256 清单作为发布 ZIP 的专属覆盖文件。辅助脚本和清单放在保留目录 `.onedeploy-openclaw/`，不会改源项目。
- 复用服务器端 deploy.sh 的事务与锁。在应用健康后调用随包脚本，再切换 current；失败调用原有回滚流程。独立阶段标记进入现有发布日志与历史。
- 容器内 Node 工作程序只操作指定插件、插件 Skill 和工作区 Skill 下清单列出的文件。拒绝符号链接，备份覆盖文件与元信息，锁定 OpenClaw 同步事务；保留不在清单内的用户文件。备份在 OpenClaw 根目录专属子目录，权限受限。
- Bash 控制程序经 docker cp 传递专属产物，使用容器现有 Node 和 OpenClaw CLI；先验证文件与加载，再按变化重启并复验。异常时按事务恢复文件并重新加载；恢复失败明确上报，不伪装成功。
- 手动回滚复用目标发布包内的同步程序。当前版本参与 OpenClaw 同步而目标版本缺少同步信息时，提前拒绝。
- 使用真实临时文件验证工作程序复制、哈希、备份恢复与异常；外部 Docker/CLI 以隔离桩验证控制流程，现有部署回归验证未启用兼容性，前端构建验证 Vue 配置界面。
