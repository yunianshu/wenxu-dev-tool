# Docker OpenClaw 随项目发布

## 需求与验收

- R1：每个部署环境可单独启用 OpenClaw 同步，配置容器名、项目内插件目录、项目内 Skill 目录及容器内 OpenClaw 根目录、工作区目录。旧配置默认关闭；保存、重新打开、复制环境后配置归属明确。
- R2：Docker 或自动 Docker 发布开启同步时，插件及两处 Skill 副本必须随本次发布包交付；本地目录越界、符号链接、缺少已构建入口或无效标识必须在发布前报错。禁用时维持原有发布行为。
- R3：应用健康后、发布成功之前更新 OpenClaw。更新前备份本次将覆盖的文件；文件一致时不重启，有变化时重启指定容器。不得更改 OpenClaw 授权、网关配置或其他插件。
- R4：插件文件、两份 Skill 内容、插件加载版本及 Skill 可见性均核验通过后才报告发布成功。容器不存在、未运行、加载失败或内容不一致必须报告失败；更新失败恢复本次改动，并按项目现有策略回滚应用。
- R5：发布进度单独显示 OpenClaw 同步阶段。回滚到包含 OpenClaw 发布信息的旧版本时同步旧产物；无法确认旧版 OpenClaw 内容时在停服务前拒绝，不能报告整体回滚成功。
- R6：配置和产物不保存 SSH 明文凭证，不扫描项目外文件；插件必须提供已构建、可独立加载的目录，不在容器中自动安装依赖或扩大工具权限。

## 范围

现有项目部署流程、配置界面、按环境存储及必要文档和测试。当前 PLM Web 原句复测已通过，OpenClaw 实际仍为 0.15.1，与待同步 0.15.2 的 14 个文件只有 3 个一致。当前任务不自动发布 project-tool 安装器、不写生产容器或更改生产授权。
