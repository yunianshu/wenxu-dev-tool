# 新项目部署文件生成规格

本功能帮助新项目根据真实构建与启动依据生成部署文件，经校验、预览和写入后接入现有发布流程。

## 范围与约束

- 保留现有 Linux Compose 与脚本部署，沿用服务器、版本、数据与回滚约定。
- 不实现移动商店发布、Windows 服务或 Kubernetes；不执行未经指定的生产部署。
- 不修改业务代码，不将项目凭据、同步数据、目录外文件或链接目标发送给 AI。

## 验收规则

1. **项目依据**：当项目缺少部署文件时，助手必须提供真实构建清单、启动入口、锁文件信息及受限目录索引；深层子模块也应识别。
2. **按需补读**：当 AI 请求项目文件时，助手必须安全补充后继续规划；越界、链接、运行凭据、二进制和同步数据必须拒绝，读取量与轮次有上限。
3. **新项目方案**：当项目无既有发布方式时，应优先使用可在服务器构建的 Compose；已有脚本契约继续兼容。无 AI 时必须明确给出缺失项，禁止生成空占位文件冒充完成。
4. **成组生成**：当用户生成部署文件时，所有相关文件必须共享项目与方案上下文，可统一预览和写入；截断输出、生成失败、文件引用不完整必须明确失败。
5. **校验与恢复检查**：当生成或写入部署文件时，必须检查允许路径、内容、Compose 引用和脚本语法；写入前保留覆盖备份，写入后重新体检并更新阻塞项。静态校验不能标记为真实构建或发布成功。
6. **上下文隔离**：当切换项目、目录、环境或关闭助手时，旧异步响应不得更新新上下文；生成、写入、套用和体检必须避免交错。
7. **交付验证**：隔离夹具必须覆盖无部署文件的项目从规划、生成、校验、写入、套用到真实发布编排边界；AI 和 SSH 可替换外部边界，必须明确未做生产部署。
