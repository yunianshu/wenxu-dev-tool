# 一键请假六项审查问题修复

开始：2026-10-23 16:41（Asia/Shanghai）。范围仅为本次确认的六项问题，以及现有北森通道的鉴权、重连与权限提示；不发布版本、不创建真实请假。

## 已确认的复现与根因

前一轮已执行真实业务函数、Vue setup 与隔离 HTTP/VM 验证，结论均为 confirmed：

1. 月度范围：本月已有五次各十分钟的覆盖余量，今天 08:40 到岗。整月方案请假 0.5 小时，单选今天却不请假。根因是读取和额度统计都局限于选区。
2. 书签鉴权：未配对来源领取任务并用任务中的回调 ID 伪造成功，后端接受。根因是 HTTP 端点缺少凭证和来源限制。
3. 调休总额：总余额 0.5、条目 2 小时，10:00 到岗分配调休 1.5，剩余 -1。根因是条目模式绕过总余额。
4. 过期响应：重算中把上班时间改为 09:00，旧响应恢复 08:30 方案。根因是工具栏未锁定且响应未校验配置代次。
5. 假种恢复：手选年假后切页，再调整计算迟到，变回调休。根因是显式选择仅保存在组件局部状态。
6. 重连：应用实例端口变化后，书签仍指向旧端口；同页旧全局标志阻止新桥初始化。根因是随机端口与不可替换的轮询实例。

## 实现约束与验收

- 读取涉及月份的完整出勤、已有申请；选区外已经发生的额度内迟到与覆盖余量优先计入，只有选区内生成申请。完整月份指纹参与提交复核；旧版范围不完整的留存方案要求重新生成。
- 调休受条目可用量及总余额的共同上限限制；多日、指定假种、分段均不超额。
- 显式 overrides 随公开方案返回、留存并恢复。重算锁跨页面保留，所有修改入口共用锁，配置改变后的旧响应不得恢复方案。
- 生产书签使用本机固定配置端口；持久配对凭据经现有系统凭据库保存，禁止明文降级。来源、Host、配对凭据及会话凭据共同校验；内嵌回调也需要独立凭据。重新配对替换旧轮询，提交不自动重发。
- 现有旧书签首次升级需替换一次；新书签跨重启可重连。端口冲突、凭据库不可用、浏览器拒绝本机网络权限都给出明确提示，保留内嵌登录兜底。
- 对六项缺陷及来源伪造、无凭据、过期会话、长轮询取消、重启重连、权限失败补回归；执行专项自测、双桥 RPC 与渲染构建。
