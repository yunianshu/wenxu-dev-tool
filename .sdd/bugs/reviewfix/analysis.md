## 项目级发布策略补充

用户明确要求数据库备份、健康检测、数据同步依项目不同处理。确认自动发布原来强制关闭数据库备份和数据同步，并覆盖自定义健康检查；现将用户策略与自动探测结果分开保存。

- 共享服务器只管理连接。项目/目标保存独立的数据库、健康和同步策略，切换服务器仅清除运行探测结果。
- 自动识别唯一明确的 PostgreSQL/MySQL/MariaDB 服务；升级前备份旧实例，首次无旧实例跳过。多库或无法识别时说明原因；支持手动或明确关闭。当前数据库恢复支持 PostgreSQL。
- 健康检查优先项目已有容器检查，也可选自定义 HTTP；保留用户配置。
- 数据源须位于当前项目，远端须位于当前安装目录，拒绝链接跨界。自动模式将匹配的容器数据挂载指向项目共享目录；没有挂载用途或导入命令时在远端操作前拦截。
- 直接挂载的数据在备份、构建成功后、启动前同步；导入命令待应用健康后运行。同步失败不启动新服务，代码回滚不撤回业务数据。

验收由真实 Bash 与临时目录夹具覆盖，Docker/SSH/外部 API 均使用隔离替身，不访问生产环境。

兼容性复审补充：旧配置明确关闭的健康检查继续关闭；编辑共享服务器的地址、端口或账号时，使所有引用目标的运行探测失效。表单和取消快照同步处理，旧表单保存不能恢复旧探测；编辑服务器名称或凭据不影响项目策略。
