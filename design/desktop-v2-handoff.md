# Personnel PLM 桌面界面重设计交付规格

本规格依据 15 张现有界面截图及当前 `src/views`、`src/components` 中的实现整理，用于配合本目录的 `.pen` 设计稿进行开发。`.pen` 是静态可编辑设计稿，不是已接线的交互原型，也不代表前端已经实现；本文的状态与交互描述属于开发契约，明确标注的新增交互均为建议。核心业务实体、数据范围、提交条件与外部写入语义保持现有实现。

## 1. 旧界面分析

### 1.1 当前信息架构

现有主导航分为三组：工作区包含工作台、项目；项目能力包含 AI 助手、DeepSeek Harness、终端工作台、活动报告、一键填报、部署；系统包含扩展管理、设置。设置再分为 AI 服务、Git 活动、个人身份、一键填报、界面、应用信息。该结构已经覆盖日常开发、活动汇总、工时与发布，保留现有页面名称和主要位置，减少迁移成本。

“项目能力”组中的页面不都受当前项目约束。项目选择驱动 AI 助手和部署；工作台与报告是全局范围，填报使用自己的项目集合，终端和 Harness 有独立工作区。不能为了统一外观，在每个页面机械加入当前项目筛选器。

### 1.2 功能区域

应用外壳承担主导航、页头、窗口控制与本地数据状态。项目页采用列表与详情，AI 页采用来源选择与对话，终端采用多窗格，部署采用运行状态、日志与历史，报告和填报采用条件区、结果区与历史记录。重设计继续使用这些符合任务的结构，不把所有页面套成同一种卡片模板。

### 1.3 用户主要任务

用户通过项目列表找到项目，打开终端或 AI 助手开展工作；随后按日期采集 Git 活动，生成和导出报告，选择项目并绑定禅道任务完成工时填报；需要上线时选择项目、环境、服务器，发布版本并检查结果。设置承担这些任务的初始配置和故障修复。

### 1.4 高频操作

根据页面入口和截图推定，高频操作包括项目搜索与切换、打开项目终端、AI 输入与发送、报告日期选择与生成、填报项目勾选与预览、发布日志查看。这是设计推断，现有仓库没有提供使用频率统计。高频入口放在固定工具栏或对象附近，避免藏入多层菜单。

### 1.5 低频操作

项目创建与元信息编辑、服务器凭据维护、Git 扫描目录与排除规则、身份配置、Harness 端口、终端字体和窗口关闭行为属于配置类操作。低频操作仍然可发现，但使用次级按钮、菜单、抽屉或设置分区；不与生成、发送、提交、发布争夺视觉焦点。

### 1.6 当前 UI 的问题

页头、工具条与区块标题之间间距偏大，表格和日志可见面积受到挤压。部分配置页横向分割线贯穿整页，表单实际只使用左侧空间。部署的服务器管理比发布更像主要操作。填报的绑定错误、工时分配、任务汇总和提交操作分散在长页面中。部分时间、版本、数字和路径未形成稳定对齐关系。多个侧栏同时出现时，视觉重量接近，主次不够明确。

### 1.7 可以删除的视觉噪音

减少每行常驻的删除按钮、重复出现的成功色标签、仅起包围作用的卡片边框、大面积空状态标语和重复标题。长路径与完整技术描述采用单行省略、Tooltip 和详情展示；操作所需信息仍保持可访问。空状态仅保留一句原因和一个下一步入口。

### 1.8 可以合并的功能展示

部署的环境、服务器与版本信息合并为连续的上下文区；项目能力入口合并为紧凑操作组；报告周期、日期与作者筛选合并为条件工具栏；填报的任务、工时与汉印比例集中到提交汇总区。这些调整合并的是展示与入口，不合并底层业务：Git 活动源不等于项目，AI 助手不等于 Harness，生成报告不等于写入工时。

### 1.9 应该强化的信息

突出当前页面的真实数据范围、选中项目、部署环境和服务器、报告采集周期、填报选中数量与总工时、未绑定项、线上与本地版本、终端焦点、进行中任务及失败原因。状态由文案与图标共同表达，不能仅靠颜色。保留本地优先的数据说明，但使用低干扰的状态栏呈现。

| 扩展管理 | 四平台技能与插件的已有本地管理；启用、禁用、查看 SKILL.md、打开目录、刷新；缺失、断链、不支持和读取失败状态 | 平台选择、技能与插件标签、紧凑列表。页面为代码推导的示例内容，无旧截图佐证；示例条目和数量不代表用户实际安装情况，不新增扩展商城或安装业务 |

### 数据范围与实体约束

- 工作台是全局总览，不使用当前项目过滤今日状态。
- 项目可没有 Git 仓库，本地目录为可选。扫描出的 Git 活动源可以尚未转换为项目，不能把活动源数量标成项目数。
- 项目列表的选中值驱动 AI 助手与部署；切换项目后，详情和上下文必须同步更新，迟到的旧请求不能覆盖新项目。
- AI 的四类来源由用户勾选，附带项目上下文开关保留。Git 活动显示真实采集周期，不硬编码“今天”。AI 服务未配置、无当前项目和无 Git 活动是不同状态。
- 活动报告当前固定汇总全部项目，不跟随当前项目。项目详情中的报告入口也不能悄悄变成单项目采集。选择周期与已有数据周期不一致时，明确提示重新生成，并禁止错误复制或导出。
- 填报独立维护所选项目。生成报告只形成待提交计划；预览不写入外部系统。勾选变化会重新计算工时和汉印比例。已选项目未绑定禅道任务时保留提交阻塞；已有当日记录的更新语义须显示。
- 部署设置属于当前项目及环境；服务器连接可以共享。项目安装目录、健康检查、数据库备份和数据同步不能因换服务器而错误继承其他项目的数据。
- 终端跨页面保持会话，应用重启恢复布局后重新启动进程；不能让界面暗示旧进程仍存活。Harness 使用自己的工作区和会话体系。
- 所有示例地址使用 `example.invalid`，账号、邮箱和路径使用明确的示例值；凭据仅显示完整遮罩，不复制截图中的尾号或内部地址。

| 页面工具栏 | 64px，承载页面标题和上下文操作；与标题栏合计 104px |

| 标题 | 区块标题 14–16px / Semibold，页面标题 22px / 600 |
| 标准数据行 | 表格行高 40px，文字 12–13px；同一表格保持统一，不使用大卡片替代行 |
| 工具栏与按钮 | 常规按钮高 32px，输入与选择器高 32px；触发面积一致 |

标题栏、页面工具栏与状态栏固定，主要工作区独立滚动。条件栏与页内标签栏按页面需要追加占用高度，不套用到每一页。长表格表头固定；采用建议分页方案时，底部分页与结果数量保持可见。终端与嵌入 Harness 使用剩余工作区高度。窗口内允许滚动，但导出的整窗截图必须包含四边、侧栏、窗口控制和状态栏。

| 窗口 | 侧栏后可用宽度 | 扣除 40 + 64 + 24px 后的基础工作区高度 | 适配方式 |
| --- | --- | --- | --- |
| 1280 × 720 | 1072px | 592px | 16px 内容边距；项目列表 256px、行高 44px；工具栏低频操作收进更多菜单；必要详情面板可采用覆盖式抽屉；路径列优先省略；主要操作始终可见 |
| 1440 × 900 | 1232px | 772px | 24px 内容边距；项目列表 280px、行高 56px；完整条件工具栏；AI 来源面板在右侧占 272px |
| 1920 × 1080 | 1712px | 952px | 增加表格、日志与终端可见内容，不等比例放大按钮或字号；详情阅读区可设最大宽度 |
| 2560 × 1440 | 2352px | 1312px | 保持同一组件尺度；分配更多空间给数据列与终端；表单和对话文字限制行宽，剩余空间用于工作区而非装饰 |

表中基础工作区高度尚未扣除按需条件栏与页内标签栏；出现条件栏时再扣除 56px 或 64px，出现页内标签栏时再扣除 44px。正文可视高度还受页面内边距和底部操作区影响。

208px 侧栏不因窗口变小自动折叠。保留用户主动收起侧栏的现有能力，恢复展开后仍为 208px；收起时提供标签 Tooltip 并记忆用户选择。表格保留身份列、关键状态和行操作，次要列可响应式隐藏后在详情查看。需要保持全部列时，仅表格内部横向滚动，不让整个应用横向滚动。

## 4. 视觉与组件

### 浅色主题与共用设计变量

| 变量 | 值或规则 |
| --- | --- |
| 背景 | `#F7F8FA` |
| 主表面 | `#FFFFFF` |
| 次表面 | `#F2F4F7` |
| 边框 | `#E5E7EB`，通常 1px |
| 主文字 | `#18181B` |
| 次文字 | `#71717A` |
| 禁用文字 | `#A1A1AA` |
| 唯一品牌色 | `#0E7A6D`，用于主要操作、当前选中、焦点、进度和必要状态 |
| 字体 | 设计正文使用 Inter；设计渲染器按可用字体处理中文 fallback。开发端中文优先 Microsoft YaHei 或 PingFang SC，并保留系统回退 |
| 等宽内容 | 终端、日志、版本和必要的代码信息使用等宽字体；不将整页普通正文设为等宽 |
| 间距 | 4、8、12、16、20、24、32px |
| 圆角 | 小组件 4–6px；按钮 6px；面板 6–8px；弹窗 8–10px |
| 图标 | 同一套 Lucide 线性图标，16、18、20px；不混入不同风格图标 |

语义错误色和警告色只表达状态，不作为第二品牌色。Hover 使用次表面或轻微明度变化；Selected 使用轻品牌底色及明确文字/图标；Focused 使用 2px 主题强调色轮廓，保持键盘可见性。避免大渐变、发光、毛玻璃、夸张阴影和大圆角。

### 黑色主题设计变量

黑色主题与浅色主题保持相同的信息结构、尺寸、间距、字体、图标与业务状态。按语义变量替换表面、文字、边框与交互状态，不对浅色画面直接执行 invert。品牌按钮底色保持 `#0E7A6D`，强调文字与焦点使用更明亮的同色系色值以适应深色背景。

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| `bg` | `#101114` | 应用基础背景 |
| `surface` | `#181A1E` | 主工作区、菜单和弹层表面 |
| `subtle` | `#24272D` | 次表面、Hover、表头或弱区分区域 |
| `border` | `#30343B` | 分隔线、控件与面板边框 |
| `ink` | `#ECEEF2` | 主要文字与图标 |
| `muted` | `#A1A7B2` | 次级说明、时间、辅助图标 |
| `disabled` | `#686E78` | 禁用文字与图标 |
| `accent` | `#72CBB9` | 强调文字、选中图标、焦点轮廓 |
| `brand` | `#0E7A6D` | 主要按钮底色；与浅色主题一致 |
| `selected` | `#19372F` | 导航、列表和表格选中背景 |
| `danger` | `#F28B82` | 危险操作文字、错误提示与相关图标 |

Primary 按钮保持清晰的浅色文字；普通次级动作不全部染成强调色。深色终端与日志保留已有可读配色，不被应用主题转换重复反相。运行中、成功、警告、失败、未绑定等标签保留语义色与状态文字；检查各自前景、背景、边框的组合，不能用统一绿色替代所有状态。

同一 `.pen` 已核实包含 24 张浅色画板与 24 张黑色画板，共 48 张，一一对应且布局不变。Pencil 对全部 48 张画板的布局检查报告问题数为 0；这属于设计布局检查结果，不等同于产品功能验证。双主题画板是静态可编辑状态示例，不意味着文件提供可点击的主题切换器，也不表示产品端已经实现主题持久化。

### 组件状态契约

| 组件 | 状态与行为 |
| --- | --- |
| Button | Primary、Secondary、Ghost、Danger 四级。每个操作阶段最多一个主要按钮；Hover/Pressed 不改变尺寸；Loading 防重复触发且保留原按钮宽度；Disabled 保留原因入口 |
| Input / Search / Select | Default、Hover、Focused、Disabled、Error；错误文案紧邻控件；搜索可清除；下拉可键盘导航；长选项显示 Tooltip |
| Checkbox / Radio / Switch | 区分未选、选中、半选、禁用；加载中的开关禁止重复提交；切换失败恢复原值并说明原因 |
| Tabs | 明确选中线或选中底色；切换不重置无关筛选；不可用状态说明前置条件 |
| Table / List / Tree | 固定表头；Hover 与 Selected 可区分；列排序指示当前方向；筛选状态和结果数可见；长内容省略后可查看；空、加载、错误使用同一内容区域 |
| Toolbar | 条件放左，主要动作放右，对象状态与上下文相邻；少量低频操作进入更多菜单；窄窗口保持主要动作可见 |
| Context Menu / Dropdown | 鼠标与键盘均可打开，Esc 关闭；危险动作放底部并分隔；不可用项禁用并说明原因 |
| Dialog / Drawer | 用于确认、配置或真实详情编辑；标题说明对象；取消与主要动作固定底部；保存中防重复提交，失败保留输入 |
| Tooltip / Toast | Tooltip 补充截断信息和图标说明，不承载唯一必要信息；Toast 用于操作反馈，可读错误同时留在相关区域 |
| Progress | 显示当前阶段、进度、耗时或可解释的等待文案；失败阶段保留日志与重试入口；不使用无限动效假装进度 |

设计中新增的搜索、过滤、排序与分页均为待实现建议，不代表现有产品或 `.pen` 已具有这些行为。项目搜索、状态筛选等代码中已有能力继续保留；其余新增入口在开发时需明确对全量数据还是当前页生效，不改变原有业务口径。未实现时不得在实际产品中放置无效控件。分页使用结果总量、当前页、页大小与前后页，不能把未知总数展示为确定值。

## 5. 页面状态与反馈

| 终端 | 无项目、无窗格、活动与非活动窗格、连接中、运行中、进程退出、启动失败、达到 4 窗格上限 |

## 6. 桌面交互规则

### 键盘

现有能力继续保留：AI 输入框 Enter 发送、Shift+Enter 换行；Harness 的全屏与退出行为；表单中已经支持的回车添加目录或身份。所有按钮、输入、标签页、下拉与行菜单应按视觉顺序可聚焦，焦点不可被固定工具栏遮挡。

以下快捷键是建议开发实现的增强，**不是当前产品已有能力**；只有完成实现后才在实际界面显示提示：

| 建议快捷键 | 范围与行为 |
| --- | --- |
| Ctrl+F | 聚焦当前页面已有搜索框；页面没有搜索时不创建额外业务 |
| Ctrl+N | 项目页新建项目；终端页打开新建终端选择菜单；其他页面不强行复用 |
| Ctrl+S | 编辑抽屉或设置表单保存当前范围；无修改时不重复保存 |
| 方向键 / Home / End | 在获得焦点的列表、树或表格中移动活动行 |
| Enter / Space | 打开当前行或切换当前复选框，具体语义在同一组件内保持一致 |
| Shift+F10 | 打开当前对象的上下文菜单 |
| Esc | 依次关闭菜单、Tooltip、可取消弹层；有未保存修改时先确认，不静默丢弃 |

发布、回滚、数据库恢复及工时正式提交不绑定单次普通 Enter；必须由明确的操作按钮及现有确认流程触发。终端获得焦点时优先把组合键交给终端，应用快捷键不得抢占 shell 的常用输入。

### 右键与双击

右键菜单仅提供该对象已有的操作。例如项目行可提供编辑、打开终端和删除；报告历史可提供查看和删除；部署历史可提供日志、更新内容和符合条件的回滚。危险项仍经过原有确认，不能因右键路径绕过校验。

双击可作为打开已有详情的建议入口，单击仍保持现有选中逻辑。双击不能直接发布、删除、提交或切换有外部副作用的状态。无右键菜单的平台使用行尾更多按钮获得相同能力。

### 多选

填报保留现有项目复选框和按所选结果重新计算的规则，表头可增加全选/半选，但仅作用于明确可见的结果范围。其他列表的多选属于待实现增强；未定义批量业务时，仅提供选择和复制现有文本，不虚构批量发布、批量删除或批量写入接口。筛选后保留隐藏选中项时，必须显示选中总数和清除选择入口。

### 拖拽与窗口行为

终端保留已有横纵分隔线拖动与比例记忆，拖动时显示 resize 光标并设置可用的最小尺寸。抽屉、Inspector 与列表栏如新增宽度拖动，应限制在工作区内并记录用户偏好。项目排序、文件导入、跨项目移动等拖放业务没有证据支持，不因视觉设计而新增；若后续实现目录拖入，只填充明确的目录输入框并经用户保存。

窗口拖动区域与可点击工具控件分开，不能让按钮点击触发拖窗。现有最小化、最大化、关闭、托盘和关闭询问保持语义。用户主动收起侧栏、终端布局与字体偏好继续持久化。

## 7. 开发验收边界

1. 四种窗口尺寸下完整显示应用外壳，主要操作不被裁切，内容滚动边界明确。
2. 默认 1440 × 900 中，208px 侧栏、40px 标题栏、64px 页面工具栏、40px 表格行及 24px 状态栏满足上述尺寸；按需条件栏为 56/64px，页内标签栏为 44px；组件使用同一间距与字体体系。
3. 项目、AI、报告、填报、部署的数据范围与业务规则符合本文约束，不用视觉统一掩盖不同范围。
4. 主按钮、Hover、Selected、Focus、Disabled、Loading、Error 在可实现组件中有明确规范；无效条件解释可见。
5. 图标使用统一库，表格不是卡片列表；数字、日期、版本与操作列保持稳定对齐。
6. 所有示例均已脱敏；地址使用 `example.invalid`，邮箱使用 `user@example.invalid`，密钥和密码只使用遮罩。
7. 新增快捷键、搜索、过滤、排序、分页、右键和双击增强在实现前标为建议，不作为现有行为陈述。
8. `.pen` 为静态可编辑设计交付，图层不承诺可点击跳转、实时筛选、拖拽或其他已接线交互；截图为完整正视窗口，不使用透视、设备模型、环境布景或宣传图构图。视觉验收以实际导出和检查结果为准，本文不替代渲染验证。
