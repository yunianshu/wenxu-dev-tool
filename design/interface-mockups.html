文须项目管理 · 新信息架构设计说明

产品定位：文须项目管理工作台。项目是一等领域对象——不要求必须是 Git 仓库，也不要求配置部署；Git 活动、AI 助手、部署是项目的可选能力。本文档取代旧的「Git·报告 / 仓库扫描 / 报告生成」设计稿，作为界面实现的对照依据。

适用范围：Electron 桌面端 · 最小窗口 1080 × 700 · 约 1 米观看距离 · 离线可用（无远程字体/外部资源）

一、信息架构：三组六入口

侧栏分三组：工作区（工作台、项目）、项目能力（AI 助手、活动报告、部署）、系统（设置）。应用顶部为统一的当前项目选择器，切换项目后 AI、报告、部署使用同一上下文；选择「全部项目」时仅工作台与报告可用聚合视图，部署仍要求明确项目。

二、页面职责

页面叙事角色职责与主操作容量策略
工作台 定向与概览 真实项目数量、当前项目资料完整度、Git 活动状态、部署状态、最近操作；快捷入口：创建项目 / 询问 AI / 生成报告 / 打开部署。不编造指标。 首屏只放真实状态与 4 个关键动作
项目 选择与维护 项目列表与详情；新建、编辑、归档/删除（危险操作确认）。字段：名称、说明、本地目录、状态、标签、备注。只填名称即可创建，Git 与部署均非必需。 列表 + 单项目详情，编辑使用抽屉
AI 助手 思考与协作 独立对话工作区；显示当前项目，可勾选上下文来源（项目资料 / Git 活动 / 报告摘要 / 部署状态）；项目级快捷问题：项目总结 / 风险梳理 / 下一步计划 / 生成项目报告。无 Git 数据也可正常对话。 对话为主，上下文来源为辅
活动报告 数据分析 日报 / 周报 / 双周报 / 月报 / 自定义周期，作者筛选、明细、统计、历史与导出；范围为当前项目或全部项目；明确标注「Git 活动是报告数据源之一」。非 Git 项目给出空状态并引导用 AI 基于项目资料整理。 筛选固定、结果独立滚动
部署 高风险执行 当前项目的发布状态、环境、主要发布动作、8 阶段进度、日志和历史；服务器、健康检查、备份等低频配置收进「部署设置」面板。发布前有确认，支持取消与回滚。 发布动作居中，配置降级到面板
设置 低频配置 按「AI 服务 / Git 活动采集 / 个人身份 / 应用信息」分区；已发现 Git 仓库仅作为数据源状态展示，不再承担项目管理入口。 分区导航，单区单职责

三、视觉系统要点

视觉温度：冷静、可靠、轻量的桌面生产力工具；不做开发者霓虹风，不使用装饰性插画。

辅助说明文字
  • #0E7A6D 是唯一主强调色，用于主按钮、当前导航、关键状态；语义色（成功 / 警告 / 危险）只用于状态，不参与装饰。
  • 白色主面 + 低饱和中性灰背景；避免大面积高饱和大色块。

排版与容器

  • 沿用跨平台中文系统字体（PingFang SC / Microsoft YaHei / Segoe UI），不引入远程字体，保证离线可用。
  • 标题通过字号、字重和留白建立层级，不依赖色块。
  • 主要页面使用页面标题、分区线、列表和少量有意义的状态面板；减少「每块内容一个圆角卡片」的堆叠。

可用性底线

  • 正文字号不小于 14px；主要点击区域不小于 40px。
  • 键盘焦点清晰可见；正文对比度达到 WCAG AA。
  • 1440×900、1280×800、1080×700 三种窗口下无页面级横向滚动、无主要操作遮挡。
  • 空项目、无 Git、无报告、未配置 AI、未配置部署五类空状态均提供单一明确的下一步。
  • 动效只保留视图切换、抽屉和状态变化的短过渡；遵守 prefers-reduced-motion。

四、文案口径

  • 除「Git 活动 / 数据源」等必要语境外，Logo、导航、页标题、空状态和产品说明不再把产品称为 Git 管理或 Git 报告工具。
  • 「仓库」一词仅在 Git 数据源语境使用；用户心智中的一级概念是「项目」。
  • 不为缺失数据制造演示指标、虚假活动或虚假 AI 结论；空状态给出真实、可执行的下一步。
